# 三份专项报告（遍历性 / 真实性 / 匹配性）

> **这三份报告是交付物的主体，不是附录。**
> 委托方（老师/甲方）检查台账时，真正会问的就三句话：
> **「该看的信源你都看了吗？」「这些事件是真的吗？」「它们符合口径吗？」**
> 一份台账 + 一份汇总数字，回答不了这三问。必须各给一份报告。
>
> 三份报告都有一个共同要求：**每一条结论都要能指回台账某一行或某个信源**。
> 做不到就不要写 —— 那是安慰剂，不是审计。

---

## 零、先明确：三问对应三道不同的证据

| 报告 | 委托方的问题 | 要拿出的证据 | 最容易糊弄过去的地方 |
|---|---|---|---|
| **① 遍历性** | 该看的信源你都看了吗 | 逐信源的「查过 / 查到 / 没内容」记录 | 只说「检索了 1408 家」，不说每家结果 |
| **② 真实性** | 这些事件是真的吗，有没有虚构 | 每条事件的原文可回溯 + 交叉源数量 + 链接可打开 | 把「渠道不通」写成「已核实」 |
| **③ 匹配性** | 它们符合口径定义吗 | 每条事件的判定链落点 + 反证排查记录 | 只给「符合 5+2」，不写命中了哪一条 |

---

## ① 遍历性报告（Coverage Report）

**核心命题：不是「我搜了很多」，而是「每一家都有记录」。**

### 必备表（这是报告的骨架，不能省）

| 信源 | 等级 | 通道状态 | 检索方式 | 检索组数 | 命中候选 | 确证入表 | 结论 |
|---|---|---|---|---|---|---|---|
| （每行一个信源） | S/A/B/C/D | 可用/需攻克/未取到 | 站内点名 / 关键词 / 无 | 数字 | 数字 | 数字 | 有线索/无线索/渠道不通 |

### 四类结论，必须区分

| 结论 | 含义 | 能不能当证据 |
|---|---|---|
| **已检索·有线索** | 检索过且拿到相关候选 | 是 |
| **已检索·无线索** | 检索过，明确没有符合口径的事件 | 是（弱证据：该源该时段没报） |
| **取不到内容** | 反爬/付费墙/索引未覆盖 | **不是**。这是我们的边界，不是事实 |
| **未检索** | 没试过 | **不是**。必须写出来，不许咽下去 |

### 必写的三个数字

1. **信源总数 / 已遍历数 / 覆盖率**（分母要说清是全部还是「可用子集」）
2. **有线索的信源数 / 进表事件数**（说明有用的是少数，这很正常）
3. **取不到内容的信源数 + 原因分类**（403 多少、付费墙多少、索引不覆盖多少）

### 交付方容易犯的三个错

- **只报总检索次数**：「做了 2500 组查询」—— 这不能证明任何一家被看过。
- **把「未取到」算成「无线索」**：前者是我看不到，后者是它没报，性质完全相反。
- **分母偷偷换**：说「覆盖 100%」但其实是「可用子集的 100%」。分母必须写出来。

### 一句话结论模板

> 信源表共 **N** 家，本轮实际检索 **M** 家（覆盖 X%）。其中 **A** 家有线索、**B** 家明确无符合口径事件、**C** 家取不到内容（原因：…）、**D** 家未检索（原因：…）。进表事件 **E** 起，来自 **F** 家信源。

## ② 真实性报告（Authenticity Report）

**核心命题：不是「我相信它是真的」，而是「任何人拿这条能自己验证」。**

### 每条事件的最小证据集

| 项 | 要求 |
|---|---|
| 原文链接 | ≥1 条**真实可打开**的出版商 URL（不是聚合链 news.google.com） |
| 原句 | 能证明「发生了什么 + 死亡/受伤数」的原文片段 |
| 交叉源 | 独立信息链条数（转载同一通稿不算 2 条） |
| 日期确证 | `article:published_time` / JSON-LD / URL 内嵌日期（三选一，写明哪种） |
| 链接状态 | 200 可打开 / 无法判定（403、正文过薄、超时）/ 404 死链 |

### 四档真实性判定（不要用「基本可信」这种词）

| 判定 | 条件 | 台账里怎么写 |
|---|---|---|
| **多源确证** | ≥2 条独立信息链 + 事实一致 + 伤亡有出处 | 置信度 A |
| **单源可信** | 1 条权威源（通讯社/官方通报/机构报告） | 置信度 B |
| **单源待补** | 只有 1 条且非权威源 | 置信度 C，备注写清「单源」 |
| **无法确证** | 抓不到正文 / 只有聚合链 / 数字无出处 | **不计入**，落兜底 |

### 必写的四个数字

1. **链接可打开率**（分子分母都要写；「无法判定」必须与「404」分开）
2. **多源 / 单源 / 单源待补 / 无法确证** 各多少条
3. **零可核信源的事件数** —— 这个必须是 **0**，不是 0 就说明有事件在裸奔
4. **死链数 + 补证结果**

### 三条硬规矩

- **404 才算死链。** 403、超时、正文过薄都是「无法判定」，不许写成「链接失效」。
- **聚合链不算信源。** `news.google.com` / yahoo / msn 转链一律替换为真实出版商。
- **「渠道不通」不许写成「已核实」。** 抓不到正文就说抓不到，标注「单源待补」或不计入。

### 一句话结论模板

> 台账 **N** 起事件，共 **M** 条信源链接，可打开 **P** 条（X%）、无法判定 **Q** 条、死链 **R** 条。多源确证 **a** 起、单源可信 **b** 起、单源待补 **c** 起。零可核信源事件 **0** 起。

## ③ 匹配性报告（Fit-to-Standard Report）

**核心命题：不是「都符合标准」，而是「每一条都能说出命中了哪一条判据、排除了哪几条反证」。**

### 必备表

| 台账行 | 事件 | 判定链落点 | 命中的判据 | 已排除的反证 | 关键依据（原句） |
|---|---|---|---|---|---|
| （每行一条） | | 硬门槛/反证N#/判据P#/兜底 | P3 等 | N1、N2、N4 均不成立 | 报道原句 |

### 判定链的四个落点（必须分开计数）

| 落点 | 含义 | 条数 |
|---|---|---|
| **计入 · 命中 P#** | 命中某条正面判据（写明是哪条） | |
| **计入 · 官方定性** | 事发地政府明确认定 | |
| **不计入 · 硬门槛** | 实施主体是国家/政府力量 | |
| **不计入 · 反证 N#** | 私人纠纷 / 索财 / 事故 / 交战状态 / 反恐战果 / 汇总条目 | |
| **不计入 · 兜底** | 定义未满足 / 证据不足 | |

**「不计入」必须写明落在哪一步。** 全写成「不符合标准」等于没判 —— 分开记才能看出机制在哪一层卡住。

### 与委托方标准原文的逐条对照

把委托方原文（老师给的 5+2、甲方的判定标准）逐条抄下来，每条注明「本库怎么操作化、落在哪条判据上」：

| 委托方原文 | 本库操作化 | 对应判据 |
|---|---|---|
| 主体非国家行为体 | 硬门槛：国家/政府力量直接排除 | 步 0 |
| 主观故意、意图造成严重社会危害 | | P2 / P4 / P7 |
| …（逐条列全） | | |

### 边界与争议（这一节最有价值，别省）

- **口径张力**：哪些情形标准没写清、我们怎么裁的、下一次遇到会不会判成另一个结果
- **争议条目**：多源数字不一致的、主体存疑的、日期有歧义的，各自怎么处理
- **已知误判风险**：哪几条最可能被推翻，为什么

### 一句话结论模板

> 台账 **N** 起事件全部走完判定链：命中正面判据 **a** 起（P1×…, P3×…, P7×…）、官方定性 **b** 起；排除 **c** 起（硬门槛 d、反证 e、兜底 f）。标准原文 8 条已逐条操作化，无悬空条款。争议 **g** 条，已在边界一节列明。

---

## 三份报告的共同红线

1. **不许出现「基本」「大致」「应该是」。** 要么有证据，要么写「未核实」。
2. **分母必须写出来。** 「覆盖 100%」不算话，「可用信源 M 家的 100%」才算。
3. **「不知道」和「查到零」分列。** 前者是我们的边界，后者是对事实的陈述。
4. **每条结论能追到台账行或信源名。** 追不到的结论删掉。
5. **数字必须从台账复算。** 不许从上一版文档抄。

## 写完之后：过一遍写作自查（必做）

三份报告是给别人看的，写完必须按 **[08-写作自查.md](08-写作自查.md)** 改一遍。
那份判据是**自带的**，不需要装任何外部 skill。最省事的三步：

1. 搜一遍禁词表（见 08 第四节），见一个改一个
2. 每份报告抽出标题看一遍：能不能只看标题就知道这节讲什么
3. 确认「推定 / 未核实 / 单源 / 渠道不通」这些交底词**还在**（08 第五节：这类词必须留，不许为了"去模糊"删掉）

如果本机恰好装了 `deai-report`，可以额外让它做一遍语言审计，但**它不是必需项** ——
没有它这套流程也必须能跑完。
