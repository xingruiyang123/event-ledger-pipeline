# S6 · 交付（报告 + 台账 + 网页 PPT）

> 交付物有三件，每件都有一个「肉眼看不出来」的失败模式。**全部靠门禁挡，不靠眼睛。**

## 一、Markdown 报告

骨架见 `assets/templates/报告骨架.md`。硬要求：

- **Executive Summary 必须是二级标题且开头**（多数验证脚本强制要求，中文写
  `## Executive Summary（执行摘要）`）
- 每个数字后面能追到台账某几行
- 「可信度与口径」单列一节（见 S5 第三节）
- 参考文献区全部是真实可回溯链接；**聚合链不算**

## 二、台账 xlsx

- 表头一列不增不减
- 只装计入的事件（排除的另存）
- 附 `已排除清单.xlsx`（含排除理由与落在哪一步）
- 附 `坐标表.xlsx`（含精度标注）

## 三、网页 PPT（单 HTML，横向翻页）

### 起手件（不要从零手写）

```bash
cp assets/templates/deck-single-file.html 交付/index.html        # 5 页骨架，已过离线门禁
python scripts/fill_deck.py --deck 交付/index.html        --from-ledger 台账.xlsx --out 交付/index.html             # 数字从台账算，不手抄
```

`fill_deck.py` 只注入 `window.DECK_VALUES`，不改页面结构 —— 想改设计就改模板，不要改生成物。
支持 `?static=1` 强制静态（无头截图必用；否则动画没跑完，条形会截成 0 宽）。

### 结构

```
交付/
├── index.html          ← 成品，双击即开
├── assets/             ← 本地 js/css/图片（motion、图标全部内联或本地）
└── shots/              ← 逐页截图（验证用，可删）
```

### 三条铁性约束

1. **外链必须为 0**：`src=` / `href=` 指向 `http(s)://` 的一律内联或本地化。
   否则断网就演示不了 —— 本项目曾经因为 4 个外链被判定不合格。
2. **单文件能离线打开**：`file://` 下浏览器会以 CORS 拦截 fetch/XHR 与 ES module。
   所以依赖库必须是 **UMD/classic 构建并内联**，数据内联为 JS 变量，**不用 fetch 读 json**。
3. **字体不依赖 Google Fonts**：用系统字体栈（`"PingFang SC","Microsoft YaHei","Noto Sans CJK SC"`）。

```bash
python scripts/gate_single_file.py 交付/index.html --pages <你的实际页数>
```

> **页数必须填你自己的数字。** 脚本默认按 `<section>` 标签计页，
> 所以每一屏必须是一个 `<section class="slide">`；用 `<div class="slide">` 会被判成 0 页。

### 验证方法（这部分比内容更容易翻车）

| 项 | 做法 | 为什么肉眼不行 |
|---|---|---|
| **动画未播完 → 截图空白** | 注入 `localStorage.setItem("<deck>-low-power","1")` 强制静态 | 模板 JS 会读 localStorage 决定低功耗模式，没值就移除 class |
| **布局溢出** | 注入脚本量卡片内所有元素 `getBoundingClientRect().bottom` 最大值 vs 卡片高度，写进 `data-diag` 属性再读回来 | 实测溢出 246px，逐页截图完全看不出 |
| **像素密度不可靠** | 用**特征色检测**（数主色像素）替代平均亮度 | 浅灰地图接近白色阈值，会误判空白 |
| **中文路径截图得废图** | 复制到 ASCII 临时路径，或起本地 `http.server` | Chrome headless 对中文 `file://` 会返回深灰图 |
| **页码顺序** | 断言 `01..NN` 连续 | 插页后手工改页码必错 |

**逐块测量定位**：溢出时打印 `children[i].offsetHeight` 找是哪一层撑破，
不是靠缩字号试。本项目就是这么算出「地图 631px vs 可用 517px」。

### 配图（如果报告要配图）

**先问槽位宽高比，再定画布比例。** 这张表能省半天返工：

| 槽位 | 画布比例 | 理由 |
|---|---|---|
| 单张全宽 | **2.2–2.4 : 1** | 16:9 屏上 contain 后受高度限制，窄图左右大留白显小 |
| 多列网格（2–3 列） | **16:10** | 每列仅约 490px，21:9 会让图只有 210px 高 |
| 1:1 方图放宽列 | 改宽扁（如 1.33） | 会撑爆行高（631px vs 可用 517px） |

三条实测踩坑：
- `bbox_inches='tight'` **会改变输出比例** → 容器 cover 会裁掉内容。改用 `tight_layout` 控边距。
- 多面板标签重叠 → 用 `gridspec(2,4,width_ratios=[0.66,1,0.66,1])` 给每列配**专属标签带**（空列）。
- grid 行写 `minmax(0,1fr)`，不是 `1fr`（后者被内容撑破）；flex 容器记得 `min-height:0`。
- HTML 批量替换**用 Python**，不要用 PowerShell `-replace` + scriptblock（会把 scriptblock 当字符串插入）。

### 内容要求（讲的人要能接得住追问）

- 每页一个主张，不要一页塞三个论点
- 关键页配「一句话结论」条
- 附 `讲稿.md`：每页对应的口述内容 + **老师/评审可能的追问与应答**
- 「演示动线」：现场演示要有可执行命令清单，且**真的跑一遍计时**

## 四、交付说明（交底，比好看重要）

`交付说明.md` 固定五段：

1. **做了什么**：一句话 + 关键数字
2. **覆盖到哪**：检索规模、时段、国家；**哪些没覆盖**
3. **哪些是推定**：行号 + 推算依据
4. **哪些交人了**：待人工审核清单指向
5. **已知局限**：精度、单源、争议项、未核完的

## 五、评分者/委托方视角自查（交付前最后一步）

开审前先答一句：**如果我是评分者/委托方，这份东西凭什么拿高分？** 答不出来就别交付。

两栏并列查：

| A 栏 · 内部一致性 | B 栏 · 外部有效性 |
|---|---|
| 能跑、能复现 | 委托方问的每件事做了几件 |
| 数字对得上 | 结论能不能落到对方看得懂的对象上 |
| 包干净、无外链 | 有没有与评分标准/需求原文对齐的指标 |
| 表头未变 | 交付物是否按「要求原文」逐条对应 |

**只有 A 栏的叫验收，不叫审查。**

**交付前做一次「陌生人 15 分钟」预演**：找没参与的人，只看交付物（不给仓库、不给解释），
15 分钟内答三问 —— 做了什么？判出了什么？凭什么信？答不出 = 不合格。
