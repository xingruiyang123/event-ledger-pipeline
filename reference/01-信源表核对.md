# S1 · 信源表核对（把「名单」审成「抽样框」）

> 大多数人拿到一份信源监测表就直接按等级从上往下用。**这是错的**，而且错得很隐蔽 ——
> 你会稳定漏掉事件高发区，却不知道自己漏了。

## 一、先认清这张表是什么

委托方给的「信源监测表 / 名录 / 白名单」通常是**渠道名录**，不是台账。
它的用途是回答「**有哪些地方可以获取信息**」。

因此**有操作性的字段只有**：`信源名称` / `主域名` / `代表URL` / `国家区域` / `重要性等级`。

⚠️ **不要**用 `分配组别` / `监测状态` / `最后监测日期` / `产出事件数` 这类流程性字段推断根因
（例如「监测状态全是未开始，说明监测链路没启动，所以没有产出回流」）。
那些常常只是模板占位字段。**这条是真实事故**：把它当根因写进结论，被用户当场纠正。

## 二、六处必查的硬伤

| # | 硬伤 | 怎么查 | 后果（不查会怎样） |
|---|---|---|---|
| 1 | **`国家区域` 语义错位** | 抽查 20 条，看填的是机构所在国还是报道覆盖范围 | 按它筛「目标国家相关」会误伤数十家（DW、The Guardian 这类国际媒体全被排除） |
| 2 | **等级结构失衡** | 算 S/A/B 占比 | 常常只有个位数百分比；「按等级优先」实际无法分配检索资源 |
| 3 | **名单缺关键机构** | 拿已知的国际通讯社/头部媒体逐一对 | 名单里根本没有国际通讯社这一层 |
| 4 | **「打不开」是本机结论** | 抽 30–50 个域名做云端/代理双通道复核 | 约三分之一「打不开」其实是本机网络或代理问题，不是站点失效 |
| 5 | **字段脏数据** | 查零宽字符、同机构异域名、区域错标 | 字符串比对会把带零宽字符的域名判成「未处理」，隐性漏源 |
| 6 | **这是名单不是台账** | 看有没有逐源检索记录 | 表里没有「查过没有/查到没有」，无法回答覆盖问题 |

## 三、可达性实测（要出三类结论，不是两类）

对每条 `主域名` 做探测，结论只有三种：

- **可用** —— 直连或代理能取到正文（状态码 200 且正文 > 2000 字符）
- **需攻克** —— 反爬/付费墙，但有可行通道
- **未取到** —— 本轮没取到内容

⚠️ **「未取到」≠「站点死亡」**。只有 **404 才算失效**。403 / 超时 / Cloudflare 都要重测。

**三条防自欺的判据**（本项目实测踩过）：

1. **Cloudflare 等待页会伪装成成功**：状态码 200、正文 31.5K 字符，内容却是「请稍候…」。
   → 攻克判定必须是 **200 且正文 > 2000 字符**；「请稍候」页不计攻克。
   实测初次判成攻克 19 个，去掉 8 个假阳性后真攻克只有 9 个。
2. **弱判据会造成大面积假阳性**：`sign in` / `log in` 在导航栏人人都有（385 条命中）；
   `become a member` 大量出现在 NGO 招募里。
   → 拆强判据（`subscribers only`、`already a subscriber`、`to continue reading`、HTTP 402）
   与弱判据（仅记录、不分级）。
3. **表内自述不可靠**：同一行可能一边标「无法访问」一边备注「可顺利爬取」；
   A 级源标「需订阅」，实测两篇文章 7000+ 字全文可取。→ 自述只作线索，实测为准。

## 四、覆盖分层（六类，逐条可复核）

把每条源落进且只落进一类：

| 类 | 含义 |
|---|---|
| 已用作信源 | 已在台账中被引用 |
| 已检索有线索 | 检索过且拿到相关候选 |
| 已检索无线索 | 检索过，明确没有相关事件 |
| 明确零结果 | 检索词命中但全是无关内容 |
| 取不到内容 | 通道不通（**不是**「没报道」） |
| 表外补充 | 台账用了但表里没有 → 应回填名录 |

**「已检索无线索」与「取不到内容」必须分列。** 前者是对事件的证据（该地区该时段确实没有），
后者什么都不是。

## 五、引用反查（这一步最能查出问题）

拿台账里已引用的域名，反向去名录里查：

- 被引用但名录标「打不开 / 无关」→ **矛盾**，要么名录错，要么台账错，必须查清
- 被引用但名录**根本没有** → 名录缺项，回填建议（附等级建议与理由）

本项目实测：台账 25 个去重域名，只有 7 个在 1408 条名录里（28%）；18 个缺项。

## 六、取源策略（这条纠正一个普遍错误）

**不要按等级从上往下取源。** 等级常常按媒体体量/流量算，不等于「会报某地具体袭击」的有用度。

正确做法：**按 `国家区域` 做目标国家匹配，等级只用于同区内的排序。**

理由（实测）：某个事件高发区对应的专向源名录里**早就有**，全压在 B/C 级；
而真正缺项的是另一些国家（名录 0 条）。

## 七、给名录的改进建议（一并交付，这是方法贡献）

1. 增加四列：**报道覆盖区域**（与机构所在国分开）、**机构类型**（通讯社/全国/地方/专业）、
   **语种**、**采集通道**（直连/代理/云端/订阅）。
2. 红/灰判定改**本机 + 云端双通道**，记录复核日期与方式。
3. `监测状态` 改成工作流字段：未检索 / 有返回 / 明确零结果 / 无返回；**无返回必须与零结果分列**。
4. 主域名规范化清洗（去零宽字符、统一 `www.`、同机构异域名归并），保留「机构—域名」一对多。
