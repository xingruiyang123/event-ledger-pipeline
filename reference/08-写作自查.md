# 交付前写作自查（自带判据，不依赖外部 skill）

> 三份专项报告、分析报告、台账备注、PPT 文字 —— 这些是**给别人看**的东西。
> 它们最常见的失败不是写错事实，是**读者读不懂**：
> 结论藏在流程叙述里、自造名词没人解释、排比句看着响亮但没信息、
> 把「我怎么做的」当成「我发现了什么」。
>
> **这一节是自带的，不依赖任何外部 skill。** 本机若装了写作类 skill 当然更好，
> 但下面的判据自己就够用。

## 一、两条总判据（先记这两条，其余都是它们的展开）

**① 前面已有铺垫 ⇒ 不必再说一遍。** 正确处置常常是**删掉重复那句**，而不是换个说法重讲。

**② 前面什么都没有、突然冒出一个名词 ⇒ 要改，且要改第一次出现处。** 加引号不是定义。

自检一句话：**这句话删掉，读者会损失什么？** 答不出来就删。

## 二、五类病灶（逐条对照自己的稿子）

### 1. 三连伪排比

- 病：`可复核、可回溯、可交付` / `更准、更快、更稳` / `有温度、有深度、有力度`
- 为什么是病：三个词都是抽象评价，没有一个能落到具体动作或数字上。读者读完不知道你到底做了什么。
- 改法：**换成一个具体动作 + 一个数字**。
  - ✗ `建立了可复核、可回溯、可交付的台账体系`
  - ✓ `每条事件都留了原文链接与发布日期出处；84 行里有 74 行能追到至少一个可打开的网址`

### 2. 无铺垫的专名

- 病：正文里突然出现`认定通道`、`兜底判据`、`信源分层`、`Event ID 体系`，全篇没解释过。
- 为什么是病：你自己知道，读者不知道。引号不是解释。
- 改法：**在第一次出现的地方用一句话说清它是什么**，后面直接用简称。
  - ✗ `按认定通道分别归档`
  - ✓ `每条事件都记了「靠什么认定它」（我们叫认定通道）：是命中了某条判据，还是当地政府直接定性`

### 3. 自造小标题 / 黑话

- 病：`数字分层说明`、`赛题工程`、`口径收敛`、`结构性发现` 这类自己起的名词当标题。
- 为什么是病：读者要靠猜才知道这节讲什么。标题的功能是**索引内容**，不是显摆概括力。
- 改法：标题直接写内容。
  - ✗ `## 三、口径收敛`
  - ✓ `## 三、为什么最终只留一套判定规则`

### 4. 缺因果链的突兀断言

- 病：`这说明信源池存在结构性缺陷。` —— 前面没有推理，突然下结论。
- 为什么是病：读者无法判断你是分析出来的还是猜的。
- 改法：**先给观察，再给判断**，两句之间用「因为 / 也就是说」连起来。
  - ✗ `这说明信源评级体系存在偏差。`
  - ✓ `名录里 75 条非洲信源，没有一家进 S/A 级，全压在 B/C。评级看起来是按媒体流量算的，但我们要的是「会报某地具体袭击」的源，两者不是一回事。`

### 5. 自指句（最隐蔽）

- 病：`本节将介绍三种方法` / `我们通过多轮迭代完成了口径统一` / `下面展示处理流程`
- 为什么是病：讲的是「我们怎么写的」，不是「我们发现了什么」。读者关心后者。
- 改法：**删掉路标句，直接进内容**；把「我们做了什么」压缩成一句放在方法节。
  - ✗ `本节将从三个维度展开对信源覆盖情况的分析。`
  - ✓ `1408 家信源里，我们实际能取到内容的有 1125 家。`

## 三、对这三份专项报告的额外要求

| 报告 | 最容易犯的写作病 | 必须做到 |
|---|---|---|
| 遍历性 | 自指句（「我们做了 2500 组检索」） | 写「每家信源的结果」，不写「我多努力」 |
| 真实性 | 模糊限定（「基本可信」「大致核实」） | 每条给原文链接 + 原句 + 链接状态三档 |
| 匹配性 | 无铺垫专名（`P7`、`N2` 直接用） | 第一次出现处写清判据内容，不写编号就算 |

## 四、语言层面的机械自查（可直接搜）

写完后把这些词搜一遍，见一个改一个：

```
不是……而是      并非……而是      不在于……而在于
与其说……不如说   看似……实则      真正       本质上
归根结底         核心是          关键在于
赋能   抓手   闭环   底层逻辑   颗粒度   组合拳   护城河
本节将   下面我们   接下来   值得强调的是   需要指出的是
```

> 这些词不是绝对禁止，但**每出现一次都要问：删掉它，意思变了吗？** 没变就删。

## 五、占位符与真实数据的边界（这一条关乎诚信）

报告里允许出现「推定」「下界」「未核实」这类词 —— **这是交底，不是语病**。
上面第 2 节的机械自查**不适用于**这类词：

| 词 | 该不该出现 | 说明 |
|---|---|---|
| 推定 / 推算 / 下界 | **必须出现** | 交代哪些数字不是实测，这是可信度的核心 |
| 未核实 / 单源 / 渠道不通 | **必须出现** | 交底比好看重要 |
| 待定 / 待补证 / 大概是 | **不许出现** | 判定只有两个值，没有第三态 |
| 基本 / 大致 / 应该是 | **不许出现** | 有证据就给数，没有就写「未核实」 |

**这一条经常被自查清单搞反**：为了「去掉模糊词」把「推定项」删掉，
结果交付物丢了最关键的交底内容。**推定要写，含糊不要写。**

## 六、最后一遍：陌生人 15 分钟预演

找没参与的人（或自己扮演），**只看交付物**（不给仓库、不给解释），15 分钟答三问：

1. 这批东西做了什么？
2. 判出了什么结论？
3. 凭什么信？

答不出来，说明不是内容不够，是**写法让内容够不着**。回去改开头和标题，不要加内容。
