# S2 · 搜集（先选数据源，再谈检索）

> **这一节的第一句话，是 2026-08 全量实测换来的：**
> **公开新闻索引适合做「专题样本」，做不了「月度全域台账」。**
>
> 实测：维基 31 天全抓 → 99 条候选 → 结构化抽取 + 战争语境分流 → 按口径只能计入 **8 条**。
> 同期尼日利亚一国官方口径就有 **500 起安全事件**。差的不是检索技巧，是**数据源的收录密度**。

## 零、先做这个判断（不然后面全是白费）

开工前必须回答：**这份台账要求「量级完整」还是「专题样本」？**

| 要求 | 数据源 | 预期条数 | 首次成本 |
|---|---|---|---|
| **月度全域台账** | **UCDP GED 正式版**（39MB，一次下载，覆盖 1989–今） | 数十至数百 | 下载一次，后续免网 |
| **最新月份**（当月/上月） | UCDP **候选集**（1.6MB，月度更新） | 十几至几十 | 每月下 1.6MB |
| **专题样本**（某组织/某国/某类型） | 公开新闻索引 + 逐源点名 | 十几至几十 | 数小时 |
| **快速摸底** | 维基「当前事件」日历 | 十几 | 1–2 小时 |

**选错源的代价**：用新闻索引做月度台账，脚本写得再好也只有个位数到十几条。

## 一、UCDP：免费、可离线、覆盖全球（月度台账的首选）

### 为什么是它

| 优点 | 说明 |
|---|---|
| **完全免费** | 无需注册、无需 API key、无需邮箱 |
| **可离线** | 下载一次 CSV，之后所有月份都能算，不依赖网络 |
| **事件级** | 每条有日期、国家、经纬度、双方行为体、死亡数、原始出处 URL |
| **覆盖全球** | 含非洲小规模袭击 —— 这正是新闻索引的死穴 |
| **口径可查** | `type_of_violence` 明确区分三类暴力，可对齐你的判定链 |

### 两个数据集，别用错

| 数据集 | 文件 | 大小 | 覆盖 | 用在哪 |
|---|---|---|---|---|
| **正式 GED** | `ged261-csv.zip` | **39 MB** | 1989 至**去年** | **月度台账（推荐）** |
| **候选集** | `GEDEvent_v26_0_9.csv` | 1.6 MB | **只含还在编码队列的月份** | 只有「最新月份」可用 |

⚠️ **最容易踩的坑**：候选集看着方便（1.6MB），但它**只保留最新在编码的月份**。
实测：2026 年候选集共 2014 条，其中 **9 月 1984 条、8 月仅 27 条** ——
8 月的数据已经移入正式 GED，候选集里只剩残余。

**所以：查历史月份必须用正式 GED；查当月/上月才用候选集。**

### 怎么下

```bash
# 正式 GED（一次下载，之后离线可算所有历史月份）
curl -C - -o ged261.zip https://ucdp.uu.se/downloads/ged/ged261-csv.zip

# 候选集（每月更新，1.6MB，适合最新月份）
curl -o GEDEvent_v26_0_9.csv https://ucdp.uu.se/downloads/candidateged/GEDEvent_v26_0_9.csv
```

下载慢就断点续传（`-C -`），39MB 在国内网络可能要几分钟到十几分钟。

### 字段怎么用（对齐判定链）

| UCDP 字段 | 含义 | 怎么用 |
|---|---|---|
| `date_start` | 事发日 | 定月份（**不要用 source_date，那是报道日**） |
| `country` | 国家 | 需归一成中文名（脚本内置 60+ 国映射） |
| `side_a` / `side_b` | 双方行为体 | **判断是否国家行为体的关键** |
| `type_of_violence` | 1=国家间 2=单方面针对平民 3=非国家冲突 | **直接对应判定链的分流** |
| `deaths_a/b/civilians/unknown` | 分方死亡数 | `deaths_civilians` 是平民死亡，判 P3/P4 时最有价值 |
| `best` | 最佳估计死亡数 | 台账「死亡人数」列用它 |
| `source_article` | 原始出处 URL | 台账「信息来源URL」列用它 |
| `where_description` | 地点描述 | 台账「地点」列 |
| `source_headline` | 报道标题 | 台账「事件摘要」列的原料 |
| `number_of_sources` | 独立信源数 | **≥2 即可判多源确证（A 档）** |

**`type_of_violence` 与判定链的对应**（这是 UCDP 最大的价值）：

| type | 含义 | 判定链起点 |
|---|---|---|
| **2** | 单方面暴力（有组织团体针对平民） | **直接进 P3/P4/P7 判定** —— 这是恐袭的主体来源 |
| **3** | 非国家冲突（武装团体之间） | 需判是否命中反证 N4（双方已交战） |
| **1** | 国家间武装冲突 | 大概率落 **M0**（国家行为体），但要查是否有针对平民的单方面行为 |

### 用脚本跑

```bash
# 从正式 GED 抽某月（推荐）
python scripts/harvest_ucdp.py --ged ged261.zip --month 2026-08 --out 候选.jsonl

# 从候选集抽最新月份
python scripts/harvest_ucdp.py --candidate GEDEvent_v26_0_9.csv --month 2026-09 --out 候选.jsonl

# 只看统计，不写盘
python scripts/harvest_ucdp.py --ged ged261.zip --month 2026-08 --json
```

## 二、公开新闻索引（补漏与专题，不是主力）

### 主路径：用你手上任何可用的检索能力

不同机器上有什么就用什么，本节不假设你有某个特定工具：

1. **`web_search`（宿主工具）** —— 几乎所有 agent 都有
2. **直接抓 URL**（requests / curl）—— 拿到候选链接后取正文与日期
3. **站内点名**（`site:域名 关键词`）—— 效果常好于宽泛检索
4. 可选增强：Tavily / TinyFish / CNKI —— 没有就跳过

**「必须逐档试过 6 档才能说检索失败」这条不成立** —— 那是给装了全部通道的机器写的。
正确判据：**至少两路独立索引交叉，且每一路失败的都记了原因**。

### 维基「当前事件」日历（快速摸底与补漏）

免费、无需密钥、每天更新、每条标原出处：

```bash
python scripts/harvest_wiki_events.py --month 2026-08 \
  --fetch-cmd "你的抓取命令 {url}" --out 候选.jsonl
```

它自带三条约束（都来自实测踩坑）：
- **数量下限**：少于 `--min-items`（默认 80）直接 exit 2
- **区分三种失败**：抓取失败 / 解析失败 / 当日空页（不许混成一个「无事件」）
- **内容校验**：某些页对 raw 接口返回网页导航壳（含 "Jump to content"），
  长度上千、状态码 200，看着像抓成功了其实一个字没有

**天花板**：维基编辑者偏欧美，非洲小规模袭击几乎不进。
实测 99 条里 76 条是俄乌/以巴/苏丹内战。

### GDELT（免费实时，但只是线索）

- **必须限速**：官方要求 5 秒 1 次，超了直接返回一句提示文本（不是 JSON）
- **粒度粗**：返回的是**文章列表**，不是结构化事件
- **用途**：找「哪家媒体在某天报了什么」，再去抓原文
- **不要**用它直接计数

## 三、多源叠加（通用性最强的做法）

没有任何单一免费源能给出「量级完整」。不同源的偏差方向不一样，叠起来覆盖率才上得去：

| 源 | 偏什么 | 强项 | 弱项 |
|---|---|---|---|
| UCDP | 有组织武装冲突 | 非洲覆盖好、可离线、有分方死亡数 | 滞后（正式版约一年） |
| 维基 | 国际关注度 | 实时、免费、每条标出处 | 偏欧美，非洲小规模几乎不进 |
| GDELT | 新闻热度 | 实时、完全免费 | 粒度粗，只是线索 |

```bash
python scripts/harvest_multi_source.py --month 2026-08 --out 候选.jsonl \
  --workdir ./数据源 --sources ucdp,wiki,gdelt
```

它会：
- 每个源一个适配器，**能连上就用，连不上跳过并记原因**（不许一个源挂了就整体失败）
- 统一字段输出
- **同国 + 同日 + 死亡数相同 → 去重合并**，并记录「来自哪些源」
- 每个源都报「给了多少条」，这是后续判断覆盖率的依据

## 四、检索矩阵（补漏阶段用）

| 类 | 做法 | 何时用 |
|---|---|---|
| **① 逐源点名** | 每个信源单独一次站内检索（`site:` 或 `allowed_domains`） | **性价比最高** |
| **② 带引号日期串按日枚举** | 多套模板 × 每天 | 第二有效 |
| ③ 国家 × 组织 × 类型 | 常见组合 | 初筛 |
| ④ 国家 × 本地语言 | 法语 / 阿拉伯语 / 斯瓦希里语 | **补非洲缺口的关键** |
| ⑤ 国家 × 周段 | 按周切 | 辅助 |

**两招最有效的都靠「具体化」**：点名到域名、点名到日期、点名到本地语种。

## 五、单域名点名，不要多域名合并

实测差异极大：多域名合并只回旧年文章；改 `site:目标域名` 立刻命中 2 篇当月专文。
**想覆盖 N 家源，就发 N 次查询。**

## 六、检索通道坏了要往下走，不许终止

```
web_search 失败（402/欠费/限流/空结果）
  → 换直连抓取（requests/curl）
  → 换站内点名
  → 换可选增强通道
  → 全都不行才说「检索不可用」，且必须列出每档失败原因
```

## 七、代理与网络（实测踩到的坑）

- **最常见的坑：代理环境变量指向一个没启动的代理。** 所有请求（含国内站）全部失败，
  看起来像「断网」。诊断：`unset HTTP_PROXY HTTPS_PROXY` 后重试；若立刻通，就是这个问题。
  Python requests 用 `session.trust_env = False`。
- **国内网络常连不上 en.wikipedia.org / 部分境外站**：用 `--fetch-cmd` 指定能取网页的命令。
- 大文件下载用 `curl -C -` 断点续传；`-m 900` 给足时间（39MB 在国内可能十几分钟）。
