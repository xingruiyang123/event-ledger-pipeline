# S2 · 搜集（穷尽不是形容词，是账目）

> 用户问「你怎么确保没有遗漏」时，唯一能站住的回答不是「我搜了很多」，
> 而是一张**可复算的检索账**：多少组查询 → 多少条候选 URL → 多少条确证 → 多少条候选事件。

## 一、检索矩阵（六类模板，按性价比排序）

| 类 | 做法 | 实测产出 |
|---|---|---|
| **① 逐源点名** | 对每个可用信源单独一次站内检索（`allowed_domains=[该域名]`） | **性价比最高**。350 源 → 644 条新增候选 |
| **② 带引号日期串按日枚举** | 12 套模板 × 31 天 + N 国 × 每日 | **第二有效**。772 组 → 4019 条 |
| ③ 国家 × 组织 × 类型 | 常见组合 | 109 组 → 608 条 |
| ④ 国家 × 查询（多语种） | 本地语言 + 英语 | 228 组 → 1443 条 |
| ⑤ 国家 × 周段 | 按周切 | 152 组 → 710 条 |
| ⑥ 按日枚举（基础版） | 4 模板 × 31 天 | 124 组 → 823 条 |

**两招最有效的都靠「具体化」**：点名到域名、点名到日期。宽泛的关键词检索召回最差。

## 二、单域名点名，不要多域名合并

⚠️ 这是实测差异极大的细节：

- 多域名合并检索：某事件只回了旧年文章
- 改成 `allowed_domains=["目标域名"]` 单域名点名：立刻命中 2 篇当月专文

**结论：逐域名点名。** 想覆盖 N 家源，就发 N 次查询。

## 三、候选池要落盘，不许只在上下文里

每天 / 每批的检索结果写入 `候选池.jsonl`，每条至少：

```json
{"url":"...","title":"...","query":"...","source_domain":"...","snippet":"...","batch":"源点名-2026-07-02"}
```

**账目结构**（最后要能一张表说清）：

| 层 | 数量 |
|---|---|
| 检索组数 | 按类分列 |
| 候选 URL（含重复） | |
| 合并去重后池内 URL | |
| 相关性筛后 | |
| 确证属目标时段 | |
| 聚类后候选事件 | |
| 与现有台账重合 | |
| **新增候选事件** | |

缺任何一层，这账就不成立。

## 四、检索通道（坏一条往下走，不许终止）

**主路径：用你手上任何可用的检索能力**（一般是 agent 自带的 `web_search` 工具、
或一个能发 HTTP 的抓取脚本）。不同机器上有什么就有什么，本节不假设你有某个特定工具。

若本机恰好装了检索路由器（多通道自动降级），可以优先用它省事，但**它只是可选加速器**：

```bash
# 可选：仅当本机确实存在这个命令时
sx search "<query>" --task auto --json     # 失败自动降级，attempts 记每档成败
```

多通道时的推荐顺序（**有什么用什么，坏一条往下走**）：

| 顺序 | 通道 | 有没有 | 备注 |
|---|---|---|---|
| 1 | `web_search`（宿主工具） | **几乎所有 agent 都有** | 工具名 ≠ 后端，后端在配置层替换 |
| 2 | 直接抓 URL（requests / curl） | 有 python 就有 | 拿到候选链接后取正文与日期 |
| 3 | 搜索引擎站内点名 | 有浏览器抓取能力就有 | `site:域名 关键词` 效果常好于宽泛检索 |
| 4 | Tavily CLI / TinyFish CLI | **可选增强** | 域名限定、抗风控；没有就跳过 |
| 5 | 知网 CNKI | **可选增强** | 中文文献 |
| 6 | Crossref / Europe PMC | 免费无需注册 | 学术类 |

**「必须逐档试过 6 档才能说检索失败」这条不成立** —— 那是给装了全部通道的机器写的。
正确判据是：**至少两路独立索引交叉，且每一路失败的都记了原因**。只有一路时，
必须在交付说明里写「仅单路检索，覆盖有限」。

**铁律**：默认检索失败 ≠ 检索不可用。除非逐档都试过并列出每档失败原因，
不许把「检索失败」当结论报给用户。**同一问题至少两路独立索引交叉。**

## 五、先做环境核验，再宣布能力不可用

任何「某能力不可用」的结论之前：

1. **先读配置层**（provider / 后端 / 密钥），不要只看工具名；
2. 发一次**真实探针**（配置在岗 ≠ 额度可用）；
3. 判据：说不可用时要能列出「核验过的路径 + 看到的返回值」。

本项目真实事故：扫了工具表没找到某个搜索工具就宣布「本机没有」，而它一直在正常工作 ——
因为那是 seam，工具名永远不变，后端在配置里。

## 六、代理与网络

- 境外站点全超时的第一嫌疑是**代理没开**。用任意方式确认：`curl -x http://127.0.0.1:PORT https://example.com`
  能通就说明代理活着（端口按本机实际填，不必是 7890）。
  此时正确动作是**如实标注「本轮实测不可行」并告知用户**，不是猜、也不是把结论降级。
- ⚠️ **最常见的坑：代理环境变量指向一个没启动的代理。** 此时所有请求（包括国内站）全部失败，
  看起来像「断网」，其实是 `HTTP_PROXY/HTTPS_PROXY` 指了个空端口。
  诊断：`unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy` 后重试一次；若立刻通，就是这个问题。
  Python requests 用 `session.trust_env = False` 或 `proxies={}` 绕过。
- 24 线程-50 线程批量抓取时务必 `verify=False` + 明确 `User-Agent` + `Accept-Language`。
- 国内站点与境外站点分开跑，避免一类全挂拖住另一类。

## S2 出口检查

- [ ] 单域名点名，不是多域名合并
- [ ] `候选池.jsonl` 已落盘，可复算
- [ ] 检索账七层齐全
- [ ] 每条失败通道都记了原因，没有一条「默认失败就停」
- [ ] 至少两路独立索引交叉
